# ENSE707 Assessment 1 Submission Checklist

The uploaded assignment brief defines seven required tasks and deliverables but does **not** provide a numerical mark breakdown for each task. This checklist therefore maps every stated requirement to evidence instead of inventing rubric weights.

## Task 1 - Problem Definition and Approval
- [ ] Background and motivation explained.
- [ ] Developers, testers, security analysts and project managers described.
- [ ] Security, reliability, performance, maintainability and usability risks identified.
- [ ] Suitability for an SQA project justified.
- [ ] One-semester feasibility/scope justified.
- [ ] Lecturer approval evidence inserted.

## Task 2 - Requirements and Quality Analysis
- [ ] Initial FRs and NFRs included.
- [ ] Clarity, completeness, consistency, correctness, feasibility and testability discussed.
- [ ] At least two weak requirements rewritten into testable form.
- [ ] Acceptance criteria included for key features.
- [ ] Quality attributes linked to measurable/observable evidence.
- [ ] Provisional thresholds clearly marked TBC rather than invented as stakeholder facts.

## Task 3 - Proposed Solution and Initial Prototype
- [ ] C# ASP.NET Core GUI runs.
- [ ] Register API and endpoints.
- [ ] Run checks and record results.
- [ ] Defect workflow works.
- [ ] Retest behaviour works.
- [ ] Dashboard works.
- [ ] CSV export works.
- [ ] Screenshots inserted in report/demonstration evidence.

## Task 4 - GitHub Copilot
- [ ] At least 3 real Copilot prompts/responses captured.
- [ ] Useful suggestion identified.
- [ ] Modified suggestion identified.
- [ ] Rejected suggestion identified.
- [ ] Human judgement explained.
- [ ] AI risk/limitations discussed.
- [ ] Team can explain every accepted output.

## Task 5 - Test Strategy and Test Planning
- [ ] In-scope/out-of-scope clear.
- [ ] Unit, integration, system and acceptance levels distinguished.
- [ ] Functional/non-functional approaches explained.
- [ ] Security, reliability, performance, usability and regression included.
- [ ] Entry and exit criteria included.
- [ ] Environment, tools, browser, dependencies and test data included.
- [ ] Risks/residual risk included.

## Task 6 - Test Cases and RTM
- [ ] At least 8 cases (package has 12).
- [ ] Positive, negative and boundary examples.
- [ ] Security and reliability cases.
- [ ] Actual execution status recorded after running.
- [ ] RTM links requirements -> acceptance criteria -> tests -> components/results.
- [ ] Traceability/change-management explanation included.

## Task 7 - Progress, Risks and Next Steps
- [ ] Work completed summary.
- [ ] Current limitations/challenges.
- [ ] Risk mitigation.
- [ ] Clear final-project plan.
- [ ] Team AI/coding/testing/QA collaboration reflection.

## Mandatory terms and evidence
- [ ] Report is 3000-3500 words (check final version in Word).
- [ ] Repository link included.
- [ ] Contribution statement for each member.
- [ ] Turnitin similarity report <=20%.
- [ ] Git commit history included/accessible.
- [ ] Do not falsify/backdate missing historical commits.
- [ ] Prepare for demonstration/viva/code review: lecturer may reduce marks substantially if understanding cannot be demonstrated.
